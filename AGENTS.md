# AGENTS.md

## Stack

React 19 SPA on TanStack Router + TanStack Start, bundled through `@lovable.dev/vite-tanstack-config` (see `vite.config.ts`). Server output is Nitro (node-server preset). Tailwind CSS v4 via `@tailwindcss/vite`, shadcn/ui-style components in `src/components/ui`, Supabase, nodemailer, framer-motion. All user-facing copy and API error messages are pt-BR.

## Commands

- `npm run dev` — Vite dev server (TanStack Start). Requires `.env` vars to match the app's specific env names (see below).
- `npm run build` — `vite build` then `node scripts/generate-shell.mjs`. The shell step rewrites `dist/client/index.html` **and** patches the Nitro SSR renderer template (`dist/server/_chunks/*.mjs`) to point at hashed assets from the Vite manifest; **do not skip it**. Docker build asserts `dist/server/index.mjs` exists.
- `npm run start` — SPA static server (`scripts/easypanel-server.mjs`) serving `dist/client`. This is NOT the same as the Docker CMD, which runs the Nitro output (`node dist/server/index.mjs`, PORT=3000, HOST=0.0.0.0). `npm start` only works after `npm run build`.
- `npm run lint` — `eslint .` **currently fails** (ESLint 9 has no `eslint.config.*` in the repo).
- `npm run format` — `prettier --write .`
- No test framework or typecheck script exists. `npx tsc --noEmit` **currently reports pre-existing type errors** (`src/routes/__root.tsx`, `src/router.tsx` `DefaultErrorComponent` props, and `vite.config.ts` `nitro.handlers` not in the config package's types) — none of these block `npm run build`. Don't treat lint/tsc failures as your regression; the reliable smoke gate is `npm run build` (the same command Docker runs).

Effective package manager is **npm** (Dockerfile uses `npm ci --legacy-peer-deps`, no `bun.lock`), despite `packageManager: bun@1.3.3`. Requires Node >= 22 (`engines` + Docker uses `node:22-alpine`).

## Routing & generated code

- File-based routes in `src/routes/`; `src/routeTree.gen.ts` is generated by the router plugin during dev/build and is committed to git. After adding/renaming a route file, run `npm run dev` or `npm run build` to regenerate it.
- API endpoints are route files with `server: { handlers: {...} }` (TanStack Start server functions): `src/routes/api/{email-marketing,track,track-stats,contact}.tsx` and `src/routes/health.tsx`. `.tanstack/` and `dist/` are gitignored.
- Client entry gotcha: `vite.config.ts` `tanstackStart.client.entry` is resolved **from `src/`**, so it must be `"client.tsx"` — `"./src/client.tsx"` silently falls back to the plugin's default entry, which means `src/client.tsx` (and anything it imports, like `@/styles.css`) never ships in the client bundle. Check the built manifest: `src/client.tsx` must be the entry key.

## /health (do not treat as duplicated/dead code)

`/health` exists twice on purpose: a Nitro handler (`server/health.ts`, wired in `vite.config.ts` `nitro.handlers`) and a TanStack handler (`src/routes/health.tsx`). The Nitro copy was added because TanStack Start `server.handlers` mis-served the route; Docker HEALTHCHECK and EasyPanel both hit `/health`. Keep both.

## Environment variables

See `.env.example`: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_KEY`, `SMTP_HOST`, `SMTP_PORT` (default 465), `SMTP_USER`, `SMTP_PASSWORD`, `SITE_URL`.

Gotcha: the browser client (`src/lib/supabase-client.ts`) reads `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` from `import.meta.env`, but `.env.example` only documents un-prefixed names. For login/auth to work in the browser you must export the `VITE_`-prefixed vars too. Server-side code (`src/lib/supabase.ts`) uses `process.env.SUPABASE_URL` + `SUPABASE_SERVICE_KEY` (no VITE prefix). Vite only exposes `VITE_`-prefixed vars to the client bundle.

## Database & auth

Schema lives in `supabase-schema.sql` (tables `email_campaigns`, `email_tracks`, view `campaign_stats`). Apply it in the Supabase SQL editor. RLS is enabled with service-role-only policies, so all data reads/writes use the service key server-side; the anon key is only used for `supabase.auth` login. If you change the schema, update this SQL file and keep policy names/idempotent statements (`IF NOT EXISTS`, `CREATE OR REPLACE`).

## Style conventions

- Prettier (`.prettierrc`): double quotes, semicolons, trailing commas, printWidth 100.
- Tailwind v4: no `tailwind.config.js`; theme is managed via CSS in `src/styles.css` (`@theme inline` + CSS variables). There is no `src/styles/` directory.
- Imports use the `@/*` alias → `src/*` (`tsconfig.json` `paths` + `vite-tsconfig-paths`), e.g. `@/lib/supabase`.
- shadcn/ui pattern: Radix primitives + `cva` (class-variance-authority) + `clsx` + `tailwind-merge` with `cn(...)`; mimic existing `src/components/ui/*` before adding new components.
- Keep pt-BR copy; user-visible strings in this codebase are generally written without accents (e.g. "nao", "voce", "Invalido").
